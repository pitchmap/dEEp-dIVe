# SPRINT_B_B6_PROPOSAL — 고가치 수송선 보상 배율·호위 거리 (DRAFT)

> **상태: 제안(DRAFT) — 승인 전. `params/economy.json`의
> `highValueTransport.rewardMultiplier`·`rewardMultiplierRange`·
> `escortMaximumDistanceMeters`는 이 문서만으로 변경하지 않는다.**
> 승인 또는 수정값 전달 후에만 입력한다.
> 근거: 7차 대회의(`meetings/12`) 결의 3 B6 / PvE 콘셉트(`meetings/10`) 결의 3.
> 검증기: `src/tools/economyMath.ts` (`validateHighValueTransport`).

## 1. 왜 수치가 비어 있는가

12차 결의 3의 B6 항목은 다음과 같다:

> B6 | 고가치 수송선 격침 보상 > 일반 수송선 (**배율은 튜닝표**)

배율은 명시적으로 **기획 튜닝표 항목**으로 위임됐고, 저장소·회의록 어디에도
공식 수치가 없다. 조사 결과:

| 찾은 곳 | 결과 |
|---|---|
| `docs/meetings/10~15` | '고가치 수송선' 개념·구조만. 수치 없음 |
| `docs/DECISIONS.md` | B-1~B-4에 배율 항목 없음 |
| `docs/templates/TUNING_LOG.md` | 고가치·호위 행 없음 |
| `params/*.json` | 배율·호위 거리 필드 없음 (이번에 스키마만 신설) |
| 코드 | 소비 지점 0건 |

따라서 **임의로 확정하지 않았다.** `null`로 두고 검증기가 미확정으로 보고한다.

## 2. 확정된 것 (수치가 아닌 구조)

승인 없이도 정할 수 있는 구조는 이번에 확정했다.

| 항목 | 값 | 근거 |
|---|---|---|
| `archetypeId` | `highValueTransport` | 계약 `HighValueTransportArchetypeId` |
| `baseDropTableId` | `cargo-standard` | 배율이 곱해지는 기준 = 일반 수송선 보상 |
| 배율 하한 | **1 초과** (검증기 강제) | 12차 B6 '고가치 보상 > 일반 수송선'에서 **파생**된 구조 조건 — 발명한 수치가 아니다 |
| 배율 상한 | 미정 | 튜닝표 항목. `rewardMultiplierRange`가 함께 도착할 때만 검사한다 |

`rewardMultiplier ≤ 1`은 B6 종료 조건 자체를 위반하므로 로드를 거부한다.
이 검사는 값이 없어도 이미 작동한다(`verify:sprint-b`의 `B3-reject`).

## 3. 제안 — 배율

현재 A 경제 곡선의 실측값을 입력으로 쓴다 (전부 확정된 값이며 이 문서에서
새로 만든 수치가 아니다):

| 값 | 출처 |
|---|---|
| 일반 수송선 보상 120 | `economy.json` `dropTables.cargo-standard` |
| 출항 최대 수입 245 | `sortieIncomeReference` |
| 보스 준비 비용 1200 | `bossReadinessReference` → 4.9회 |

### 제안 P1 — 배율 2.5 (범위 2.0 ~ 3.5)

고가치 수송선 보상 = 120 × 2.5 = **300크레딧**.

| 근거 | 내용 |
|---|---|
| 한 척이 출항 한 번을 대체하지 않는다 | 300 < 출항 최대 수입 245 + salvage… 는 아니다 → 300 > 245이므로 **한 척이 출항 1회를 넘는다**. 아래 4절의 위험 평가 참조 |
| 호위 위험의 대가 | 구축함 AI에게 쫓기는 위험을 감수할 유인이 필요하다 (10차 결의 3: '자초하는 긴장') |
| 보스 준비 단축 | 1200 ÷ (245 + 300) ≈ 2.2회 — 4~6회 목표를 크게 벗어난다 |

**P1은 보스 준비 곡선을 깨뜨린다.** 아래 P2를 권고한다.

### 제안 P2 (권고) — 배율 1.8 (범위 1.5 ~ 2.5)

고가치 수송선 보상 = 120 × 1.8 = **216크레딧**.

| 검증 항목 | 결과 |
|---|---|
| B6 종료 조건 (고가치 > 일반) | 216 > 120 ✅ |
| 출항 1회 최대 수입 | 245 → 461 (고가치 1척 추가 시) |
| 보스 준비 출항 횟수 | 1200 ÷ 461 ≈ **2.6회** |

여전히 4~6회 목표를 벗어난다. **고가치 수송선은 매 출항 등장이 아니라
조건부 등장이어야 곡선이 유지된다.** 이것이 아래 D-B6-2다.

### 제안 P3 — 배율 1.8 + 등장 빈도 제한

고가치 수송선이 **매 출항 등장하지 않으면** 평균 수입 증가가 완만해진다.
예: 3회 중 1회 등장 → 평균 수입 245 + 216/3 = 317 → 1200 ÷ 317 ≈ **3.8회**.

등장 빈도는 **월드·레벨 배치 소유**이며 경제 params가 정할 항목이 아니다.
따라서 이 제안은 배율만 정하고, 빈도는 별도 결정으로 넘긴다.

## 4. 위험 평가

| 위험 | 내용 |
|---|---|
| **보스 준비 곡선 붕괴** | 고가치 수송선이 매 출항 등장하면 어떤 배율이든 4~6회 목표를 깬다. 배율보다 **등장 빈도**가 곡선의 지배 변수다 |
| 호위 미구현 | 호위함 교전 진입은 기존 구축함 AI에 의존하는데 **구현체가 없다**(`B5_BLOCKED_NO_DESTROYER_IMPLEMENTATION`). 호위 없는 고가치 수송선은 '위험 없는 고보상'이 되어 밸런스가 무너진다 |
| 이탈 거리 미정 | 호위가 얼마나 따라붙는지가 정해지지 않으면 '유인 후 격침' 전략이 무료가 된다 |

## 5. 결정이 필요한 항목

| # | 항목 | 선택지 | 제안 |
|---|---|---|---|
| **D-B6-1** | 보상 배율 | P1 2.5 / **P2 1.8** / 기획 지정값 | **P2 1.8** (범위 1.5~2.5) |
| **D-B6-2** | 등장 빈도 | (a) 매 출항 (b) 조건부·확률 (c) 특정 해역 한정 | **(b)** — (a)는 배율과 무관하게 곡선을 깬다 |
| **D-B6-3** | 호위 이탈 상한 거리 | 기획 지정값 | **미제안** — 근거로 삼을 실측이 없다. 호위 AI 구현 후 실측으로 정할 항목 |
| **D-B6-4** | 호위 미구현 상태에서 B6 도입 여부 | (a) 배율만 먼저 (b) 호위 구현까지 보류 | **(b)** — 위험 없는 고보상은 밸런스 왜곡 |

**D-B6-3은 제안 수치를 내지 않는다.** 근거 없는 거리값을 지어내는 것은
'데이터 없는 밸런스 변경 금지'(CLAUDE.md 규칙 13) 위반이다. 호위 AI가
움직이는 것을 보고 정할 항목이다.

## 6. 승인 후 실행

1. `params/economy.json`의 `highValueTransport.rewardMultiplier`·
   `rewardMultiplierRange`에 승인값 입력
2. `verify:sprint-b`의 `B6-multiplier`가 `pending` → 자동 판정으로 전환
   (배율 > 1, 범위 내, 소비 지점 존재를 단언)
3. 게임플레이 창이 배율을 소비하도록 배선 (보상 계산은 게임플레이 소유)
4. 커밋 태그 `[ECON]`
