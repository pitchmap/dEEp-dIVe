# RENDER_SPIKE_XRAY — X-ray 반투명 렌더 기술 스파이크 판정

> 1주차 최우선 과제 (R5, 마스터 플랜 §3.7·§5.17 [보호 목록 '침수 표시']).
> 담당: 그래픽스. 스파이크 코드: `src/render/xray/XrayFloodingSpike.ts`.
> 실행 방법: 빌드·개발 서버에서 URL에 `?xray` 플래그 추가.

## 1. 성공 기준 (사전 정의)

| # | 기준 | 근거 |
|---|---|---|
| 1 | 반투명 선체 너머로 **구획별 수위 상승이 판독 가능** (1순위 = 침수 가시화, 컷 불가) | §3.7 |
| 2 | 새 렌더링 라이브러리·셰이더 프레임워크 없이 표준 Three.js 머티리얼만 사용 | 스택 확정 §7.1 |
| 3 | 성능 예산 침식 없음: 조명 추가 0, 실시간 그림자·반사 없음, 드로우콜 증가 10 이내 | §12 |
| 4 | 기본 게임 장면과 분리된 모듈이며, 스파이크가 실패해도 기본 장면·빌드는 정상 작동 | 스텁 금지·격리 원칙 |

## 2. 구현 기법

- **선체 반투명:** `transparent + opacity 0.28 + depthWrite:false + renderOrder 최후 + FrontSide`
  — 깊이 기록을 끄고 마지막에 그려, 내부 오브젝트를 깊이 차폐 없이 비쳐 보이게 한다.
  2패스 렌더·스텐실·커스텀 셰이더 불필요.
- **구획·수위:** `EdgesGeometry` 윤곽선 4구획 + 수위 박스(`scale.y = severity`,
  바닥 기준 차오름). 지오메트리·머티리얼은 구획 간 공유(각 1개 생성).
- **심해 판독성:** 수위·선체에 약한 `emissive` — 어두운 장면에서도 게임 정보가
  판독된다. 조명 수는 증가하지 않는다 (예산 2개 유지).
- **격리:** 장면 측(`CanyonScene.mountXraySpikeIfRequested`)이 try/catch로 장착.
  생성 실패 시 경고 로그만 남기고 기본 장면은 계속 작동한다.

## 3. 판정 결과: **성공** (대체 경로 발동 불필요)

- 헤드리스 Chromium + SwiftShader(소프트웨어 GL) 환경에서 검증 — GPU 가속이
  없는 최악 조건에서도 수위·구획·선체 실루엣이 정상 렌더됨. 내장그래픽
  하한(G1) 신호 양호.
- 수위 박스가 반투명 선체 너머로 명확히 판독됨 (성공 기준 1 충족).
- 추가 의존성 0, 커스텀 셰이더 0 (기준 2 충족).
- 드로우콜 증가: 선체 1 + 구획 윤곽 4 + 수위 4 = 9 이내 (기준 3 충족).
- `npm run typecheck`·`build`·`check:size` 통과, `?xray` 미지정 시 완전 비활성
  (기준 4 충족).

## 4. 확인된 위험·한계 — D13~14 본 통합 시 재확인 항목

1. **반투명 정렬:** 선체가 depthWrite:false이므로 이후 도입되는 반투명
   오브젝트(소음 파문, 폭발 이펙트)와 `renderOrder` 조율 필요.
2. **선체 자기 겹침:** FrontSide 단면 렌더로 회피 중 — 최종 잠수함 모델(D+8,
   2,000트라이)이 오목 형상을 포함하면 겹침 아티팩트 재검토.
3. **시연 값의 경계:** autoDemo 수위 순환은 렌더 검증용이다. 본 통합에서는
   `floodingChanged(compartment, severity)` 이벤트 구독으로 교체하며, 렌더는
   심각도 값을 계산하지 않는다 (판정은 게임플레이 소유).
4. **구획 수 4는 시연용** — 실제 구획 키·개수는 게임플레이 정의를 따른다.

## 5. 대체안 필요 여부

**불필요.** 확정 대체 경로(구획 아이콘 점멸 UI, 게임플레이 0.5일 이관)는
발동하지 않는다. 단, D13~14 본 통합에서 위 1·2 항목이 실기기 검증에 실패하면
대체 경로 재발동 여부는 개발 리드 판정 사항이다 (R5 대응 절차 유지).
