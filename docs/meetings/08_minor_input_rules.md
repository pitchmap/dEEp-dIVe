## 안건 1. PC 버전 화면 조준·발사 버튼

**정하늘:** "현황부터. 4차 결의 3에서 우클릭 홀드 조준 + 좌클릭 발사를 채택하면서, 화면 버튼은 '모바일용 백로그'로 보냈습니다. 그런데 이 문구가 애매합니다 — PC에서도 화면 버튼이 필요한가에 대한 판단 없이, '모바일'이라는 딱지만 붙여서 치운 거예요."

**임찬영:** "빌드 담당으로서 도입 찬성입니다. 근거는 셋입니다.

첫째, **Pointer Lock 진입 문제.** 브라우저 정책상 마우스 잠금은 사용자의 클릭으로만 시작됩니다. 어차피 '클릭해서 시작하세요' 같은 화면 요소가 하나는 필요해요. 그 요소가 조준 버튼이면 자연스럽습니다.

둘째, **첫 어뢰 60초 게이트.** 처음 온 유저가 우클릭 홀드를 스스로 발견할 확률은 낮습니다. 조작 안내 UI(`H` 토글)가 있지만, 화면에 '조준' 버튼이 보이는 것 자체가 안내입니다. 버튼은 튜토리얼을 겸합니다.

셋째, **공수.** 조준·발사 로직은 이미 세진 님이 만듭니다. 버튼은 같은 함수를 호출하는 껍데기라 0.5일이면 됩니다."

**박태현:** *(반대 1건)* "저는 화면을 어지럽히는 게 걱정입니다. 우리 게임의 화면 문법은 '사운드가 1차 정보, 시각은 축약'이었어요. UI도 3계층에서 2계층으로 깎은 마당에(3차 결의 3), 버튼 두 개가 상시로 떠 있으면 그 절제가 무너집니다. 그리고 하나 더 — 마우스 조준과 버튼 조준이 **다른 조준 시스템**으로 갈라지면 밸런스 테스트가 두 배가 됩니다."

**임찬영:** "두 번째 우려는 원천 차단하죠 — **버튼과 마우스는 동일한 조준·발사 시스템을 호출합니다.** 버튼 '조준'을 누르면 우클릭 홀드와 같은 상태에 진입하고, '발사'는 좌클릭과 같은 함수입니다. 입력 경로만 둘이고 시스템은 하나. 코드로도 `AimSystem.enter()` / `AimSystem.fire()` 두 진입점만 존재하게 강제하겠습니다."

**김세라:** "첫 번째 우려(화면 절제)는 아트에서 받겠습니다. 버튼을 화면 우측 하단에 두되, **반투명 + 소형**으로 하고, 마우스 조준을 3회 이상 사용한 유저에게는 자동으로 더 흐려지게(사용 안 하면 존재감을 줄임) 하면 됩니다. 완전 숨김 옵션도 `H` 안내 UI에 붙이고요."

**박태현:** "동일 시스템 호출 + 반투명·숨김 옵션이면 두 우려가 다 해소되네요. 철회합니다. 대신 튜닝표에 행 하나 추가합니다 — 버튼 사용률을 계측해서, PC 유저의 버튼 사용률이 유의미하면 버튼 크기·위치를 조정하는 기준으로 씁니다."

**정하늘:** "채택. 세진 님, 진입점 2개 구조로 이견 없죠?"

**오세진:** "없습니다. 오히려 진입점이 명시되면 나중에 게임패드 붙일 때도 같은 자리에 꽂으면 되니까 좋은 설계입니다."

> **결의 1:** 4차 결의 3 보완 — **PC 버전에도 화면 우측 하단에 '조준'·'어뢰 발사' 버튼을 제공한다. 마우스 조작과 화면 버튼은 동일한 조준·발사 시스템(`AimSystem.enter/fire`)을 호출하며, 플레이어가 두 방식 중 하나를 선택할 수 있다.** 버튼은 반투명·소형, 마우스 사용 유저에게는 존재감 자동 축소, `H` UI에서 완전 숨김 가능. 버튼은 Pointer Lock 진입 요소를 겸함. 공수 0.5일(임찬영), 버튼 사용률 계측 행을 튜닝표에 추가(박태현). '모바일용 백로그' 문구는 '터치 최적화 배치는 백로그'로 정정.

## 안건 2. `A/D` 단독 입력 시 프로펠러 회전 규칙

**정하늘:** "두 번째 구멍입니다. 4차 결의 6은 프로펠러를 '실제 전후 속도값'에 연결했습니다. `W` 정회전, `S` 역회전, 충돌·감속 시 함께 감속 — 여기까지는 명확한데, **`A/D`만 눌렀을 때**의 규칙이 없습니다. 사전자료 별첨 문서에도 'A/D는 추진 상태에 따라 회전 유지'라고만 되어 있고, 정지 상태에서 A/D만 누르면 어떻게 되는지는 공란이에요. 지금 구조에서 잠수함은 정지 상태에서도 제자리 선회가 됩니다."

**한도윤:** "아트 입장에서는 돌았으면 합니다. 플레이어가 키를 눌렀는데 프로펠러가 미동도 없으면 '입력이 씹혔나?' 싶어져요. D+5 사태의 핵심이 '입력 결과를 모르는 상태'였잖아요. 저속으로라도 돌려주는 게 피드백 원칙에 맞습니다."

**오세진:** *(반대)* "그 논리에는 빈틈이 있습니다. **A/D를 누르면 선체 자체가 돌아갑니다.** 화면 전체가 회전하는 것보다 강한 피드백은 없어요. 프로펠러까지 돌리면 오히려 거짓말이 됩니다 — 프로펠러가 도는데 전진하지 않는 상태를 시각적으로 만들거든요. 4차 결의 6의 원칙은 '프로펠러 = 실제 속도의 물증'이었습니다. 속도가 0인데 프로펠러가 돌면 그 물증 가치가 깨집니다."

**김세라:** "세진 님 말이 원칙적으로 맞는데, 그러면 반대로 물어야 합니다 — **정지 상태에서 제자리 선회가 되는 것 자체가 맞나요?** 실제 잠수함은 추진력 없이는 방향타가 무의미합니다. 물살이 방향타를 지나가야 도니까요. 제자리 선회를 허용하는 한 '프로펠러는 안 도는데 배는 돈다'는 그림 자체가 이미 물리적으로 이상해요."

**박태현:** "거기서 멈춰주세요. 제자리 선회 제거는 오늘 안건이 아니라 **조작감의 근간**입니다. 우리는 시뮬레이터가 아니라 '시뮬레이션의 감정'을 만들기로 했고(1차 결의 1), 좁은 협곡에서 정지 상태로 방향을 트는 조작은 캐주얼 접근성의 핵심이에요. 전진해야만 돌 수 있게 바꾸면 조작 난이도가 한 단계 올라가고, 60초 게이트가 흔들립니다."

**정하늘:** "정리하겠습니다. 선택지는 셋입니다.

- **가안:** A/D 단독 입력 시 프로펠러 저속 회전 (피드백 우선, 물리적 거짓말 감수)
- **나안:** A/D 단독 입력 시 프로펠러 정지 유지 (속도 연동 원칙 고수)
- **다안:** 제자리 선회 제거, 전진 중에만 선회 (물리 정합성 우선, 조작감 희생)

다안은 태현 님 지적대로 조작 근간을 건드리므로 오늘 범위 밖. 가안 대 나안인데 — 세진 님, 나안에서 도윤 님의 '입력 씹힘' 우려를 해소할 방법 있습니까?"

**오세진:** "있습니다. 4차 결의 6에 이미 '입력 없음 = 정지 **또는 매우 느린 공회전**'이 있어요. 공회전을 기본으로 살리면, A/D만 눌러도 프로펠러는 공회전 상태로 미세하게 돌고 있습니다. 즉 '완전 정지한 쇳덩이'는 화면에 존재하지 않아요. 규칙은 단순해집니다 — **프로펠러 회전 속도는 오직 전후 속도값의 함수이고, 하한이 공회전이다.** A/D는 이 함수에 아무 항도 추가하지 않습니다."

**한도윤:** "…공회전이 상시 깔려 있으면 제 우려는 해소됩니다. 제가 걱정한 건 '완전 정지 프로펠러'였으니까요. 철회합니다. 대신 공회전 속도를 아트에서 확인하게 해주세요 — 너무 느리면 정지로 보이고, 너무 빠르면 전진 중으로 보입니다."

**김세라:** "저도 나안으로 접습니다. 다만 회의록에 남겨주세요 — **제자리 선회의 물리적 어색함은 인지된 리스크**입니다. 플레이테스트에서 '배가 이상하게 돈다'는 응답이 나오면, 그때 다안(전진 요구 선회)이나 '정지 시 선회 속도 감소' 같은 절충을 튜닝표에서 다룹니다. 지금 결정은 '문제없다'가 아니라 '조작감을 우선한다'입니다."

**박태현:** "공정한 기록입니다. 그리고 세라 님 절충안은 지금 바로 튜닝표에 행으로 넣을 수 있겠네요 — 판단 기준까지 명확하니까."

**튜닝표 추가 행 (회의 중 작성):**

| 항목 | 초기값 | 조정 범위 | 변경 판단 기준 | 담당 |
|---|---|---|---|---|
| 프로펠러 공회전 속도 | 최대 회전의 8% | 5~15% | 정지로 보인다(아트 판정) → 증가 / 전진 중으로 오인 → 감소 | 한도윤 |
| 정지 시 선회 속도 배율 | 100% (전진 시와 동일) | 40~100% | "배가 이상하게 돈다" 2인 이상 → 감소 / 협곡 이탈 실패 관측 → 유지 | 박태현 |
| 화면 버튼 사용률 | 계측 전용 | — | PC 유저 사용률 30% 이상 → 버튼 확대 검토 / 5% 미만 → 기본 흐림 강화 | 임찬영 |

> **결의 2:** **나안 채택** — 프로펠러 회전 속도는 오직 잠수함의 실제 전후 속도값의 함수이며, 하한은 공회전(최대 회전의 8%, 튜닝 대상). **`A/D` 단독 입력은 프로펠러 회전에 어떤 영향도 주지 않는다.** 입력 피드백은 선체 회전 자체와 상시 공회전으로 충족. 제자리 선회의 물리적 어색함은 인지된 리스크로 기록하고, 플레이테스트 응답 발생 시 '정지 시 선회 속도 배율' 튜닝 행으로 대응. 방향타 애니메이션 P2 유보는 변동 없음.
