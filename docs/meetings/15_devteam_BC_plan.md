## 안건 1. 사전 확정의 지위 — "미리 정한 계획은 언제 거짓말이 되는가"

**오세진:** *(강한 반대)* "사전 확정 자체에 반대합니다. A를 아직 시작도 안 했는데 B·C 범위표를 오늘 확정하면, **A에서 배울 것들을 반영할 통로가 없습니다.** 예를 들어 A에서 구매 트랜잭션을 만들다가 저장 계층의 구조가 바뀌면? C의 정산·저장 항목은 오늘 문구 그대로면 이미 낡은 계획이에요. 우리가 13차에서 '문서발 회귀'를 그렇게 경계했는데, 오늘 회의록이 미래의 낡은 문서가 되는 겁니다. 전환 시점에 여는 게 맞습니다."

**정하늘:** "그 우려의 절반은 맞고 절반은 과합니다. 갈라서 보죠. B·C 범위표에서 **바뀔 수 있는 것**은 세부 구현 경로이고, **바뀌지 않는 것**은 항목의 목록입니다 — B1~B7, C1~C9는 7차 대회의와 13차가 확정한 종료 조건이라 우리가 오늘 뭘 하든 그대로예요. 범위표는 그 확정 항목을 창에 배정하는 표일 뿐입니다. 절충안 —

**조건부 사전 결의 + 발효 게이트.** 오늘 결의한 B·C 범위표는 즉시 효력이 없고, 각각 발효 조건이 붙습니다.

- B 범위표 발효 조건: **A 통합 PR 병합**
- C 범위표 발효 조건: **B1~B5 통과**

발효 시점에 15분짜리 **발효 확인 절차**를 갖습니다 — 안건은 단 하나, '직전 스프린트에서 배운 것 중 이 범위표를 고쳐야 하는 게 있는가.' 없으면 즉시 발효, 있으면 **바뀐 부분(diff)만** 논의해서 각주 개정. 표 전체를 다시 짜는 회의는 없습니다. 세진 님 우려(학습 반영 통로)는 발효 게이트가 받고, 제 우려(전환일 낭비·급조)는 사전 결의가 받는 구조입니다."

**오세진:** "…diff만 논의한다는 제약이 핵심이네요. 그거 없이 '확인 절차'라고 하면 결국 전체 재논의가 됩니다. diff 한정 조건으로 철회합니다."

**임찬영:** "발효 확인의 형식도 정하죠 — 회의가 아니라 **체크리스트 문서**로. '변경 필요 항목: 없음/있음(목록)'을 각 창 주인이 서면 제출하고, 전원 '없음'이면 회의 자체를 생략하고 발효. 있을 때만 모입니다."

> **결의 1:** B·C 범위표를 **조건부 사전 결의**로 채택 — B 발효 = A 통합 PR 병합 / C 발효 = B1~B5 통과. 발효 시 **서면 발효 확인**(각 창 주인이 변경 필요 여부 제출, 전원 '없음' 시 무회의 발효, '있음' 시 diff 한정 소회의). 표 전체 재작성 금지. B1~B7·C1~C9 항목 자체는 상위 결의 사항으로 본 회의의 개정 대상이 아님.

## 안건 3. B6·B7 병렬 트랙 — 반쪽짜리 작업은 누구의 창에서 도는가

**임찬영:** "13차에서 B6·B7을 'C·보스와 병렬'로 정했는데, 실행 관점의 공백이 있습니다. C가 발효되면 5창은 전부 C 범위로 교체됩니다. 그럼 **B6·B7은 어느 창에서 돕니까?** 범위 고정 규칙대로면 C 창에 B 작업을 입력할 수 없는데, 병렬 마감하라는 항목이 입력될 창이 없어요."

**정하늘:** "어제 만든 방화벽에 우리가 갇혔네요. 규칙을 하나 추가해서 풉니다 — **병렬 슬롯.** 각 창의 범위표에 '주 트랙(C 항목)'과 별도로 '병렬 슬롯(직전 스프린트의 최종 종료 조건)'을 명시 칸으로 둡니다. C 기간 중 —

- 게임플레이 창 병렬 슬롯: B6 보상 배율 튜닝 지원 (태현 님 튜닝표 실측 대응)
- 빌드·툴 창 병렬 슬롯: B7 측정 세션 운영·데이터 집계

단, **병렬 슬롯 상한 = 주당 작업 시간의 20%.** 상한이 없으면 병렬이 주 트랙을 잠식하고, 상한이 있으면 '병렬 = 무기한 방치'도 막힙니다."

**오세진:** *(이견 1건)* "20% 상한에 하나만 — 컨텍스트 전환 비용이 있습니다. 매일 20%씩 쪼개면 하루 두 번 머리를 갈아끼워야 해요. **주 1회 몰아서** 쓰는 걸 허용해주세요. 금요일 오후를 병렬 슬롯 데이로."

**정하늘:** "상한의 취지는 총량이지 배분이 아니니, 몰아 쓰기 허용. 채택."

> **결의 3:** **병렬 슬롯 제도 신설** — 범위 고정 규칙의 예외로, 각 창 범위표에 직전 스프린트 최종 종료 조건(B6·B7)을 병렬 슬롯으로 명시. C 기간 배정: B6 = 게임플레이 창 / B7 = 빌드·툴 창. **상한 주당 20%, 몰아 쓰기 허용**(주 1회 병렬 슬롯 데이). 병렬 슬롯 커밋은 [ECON]/B7 태그로 주 트랙과 분리 추적.

## 안건 5. C에서 미리 보이는 규격 공백 — 파괴 정산의 저장 시점

**임찬영:** "C 범위표를 짜다가 13차 결의 4의 구멍을 하나 미리 발견했습니다. 현행 저장 시점 5종 — 귀환 정산 확정 / 희귀 부품 즉시 / 구매 직후 / 장착 변경 직후 / 출항 확정 직전. 전부 '좋은 일' 아니면 '기지의 일'이에요. 그런데 C7의 **파괴 정산**은? 플레이어가 파괴되고 크레딧 일부를 잃는 그 순간의 저장 시점이 목록에 없습니다. 저장 없이 실패 화면만 띄우면 — 새로고침으로 **손실을 무효화**할 수 있어요. 죽기 직전 상태로 돌아가는 게 아니라, 손실 차감 전 상태가 복원되는 겁니다. '귀환이냐 한 탕이냐'의 긴장이 F5 한 번에 무너집니다."

**오세진:** "심각한 지적인데, 반대 방향의 함정도 봐야 합니다 — 파괴 '순간'에 저장하면 안 됩니다. 파괴 연출(X-ray 침수→암전) 중에 크래시가 나면 어중간한 상태가 저장돼요. 저장은 **정산 확정 시점**이어야 합니다. 손실 계산이 끝나고 실패 정산 화면이 뜨는 그 시점."

**정하늘:** "그럼 개정은 문구 하나로 됩니다 — 저장 시점 1번 '귀환 정산 확정'을 **'정산 확정(귀환·파괴 공통)'**으로 확장. 귀환이든 파괴든 정산이 확정되는 순간 저장. 신규 시점 추가가 아니라 기존 시점의 정의 확장이라 트랜잭션 구조(보완분 결의 7)도 그대로 적용됩니다 — 손실 차감·정산 기록·저장이 한 덩어리, 실패 시 롤백."

**남유리:** "연출 접점 — 그럼 실패 화면에 '기록 저장됨' 같은 표시는 넣지 말죠. 정산이 곧 저장이라는 걸 시스템이 보증하니까, 화면은 손실 보고에만 집중하게."

> **결의 5:** 13차 결의 4 각주 개정 — 저장 시점 1번을 **'정산 확정(귀환·파괴 공통)'**으로 확장. 파괴 정산은 손실 차감·기록·저장을 단일 트랜잭션으로 처리(원자성 규격 준용), 저장 시점은 파괴 순간이 아닌 **정산 확정 시점**(연출 중 크래시 대비). 새로고침에 의한 손실 무효화 시나리오를 C 자동 검증에 단언 테스트로 추가(C7-T: 파괴 정산 후 재접속 → 손실 반영 상태 유지).

## 안건 6. 스프린트 공통 규칙의 일반화 — 매번 다시 정하지 않기 위해

**정하늘:** "마지막으로, A·B·C에서 반복된 규칙을 스프린트 무관의 **상설 규칙**으로 승격해서, 이후 전환 때 논의 자체가 필요 없게 만듭니다.

1. **창 체제**: 5창(구현 4 + 통합 1), 창에는 현행 스프린트 범위 + 병렬 슬롯만 입력
2. **병합 순서**: 리드 → 게임플레이 → 그래픽스 → 툴링 (생산자→소비자→검증자 원리) — 스프린트마다 재논의하지 않음
3. **통합 창**: 리드 겸임, 코드 작성 금지, 리드 창 병합은 빌드·툴 담당 교차 승인
4. **판정**: 각 창 로컬이 아닌 dev 통합 빌드의 종료 조건 검증으로만
5. **방아쇠**: 통합 PR 병합(또는 핵심 게이트 통과)만이 다음 스프린트 착수 허가 — 사전 브랜치 병합 금지
6. **발효**: 사전 결의된 범위표는 서면 발효 확인(변경 없음 시 무회의 발효, 있음 시 diff 한정 소회의)

이 7조를 상설화하면 보스 본개발 전환 때도 범위표만 짜면 됩니다."

**서지우 (배석 발언):** "기획 접점 두 개만 — 첫째, 보스 본개발의 범위표는 오늘 안 짭니다. C를 지나면서 보스 규격(분절 애니 스파이크 결과, 패턴 세부)이 확정되니, 그건 C 발효 확인 때 함께 예고하고 별도 소회의로. 둘째, B7 병렬 슬롯의 측정 세션은 기획 주관(테스터 섭외·인터뷰)과 툴 창(로깅·집계)의 협업이니, 세션 일정은 제가 태현 님과 잡아서 찬영 님 병렬 슬롯 데이에 맞추겠습니다."

**전원:** 이견 없음.

> **결의 6:** 상설 규칙 7조 승격(창 체제·병합 순서·통합 창·판정·방아쇠·발효·병렬 슬롯) — 이후 스프린트 전환 시 재논의 없이 적용. 보스 본개발 범위표는 사전 확정 대상에서 제외(C 진행 중 규격 확정 후 별도 소회의). B7 측정 세션은 기획-툴 협업으로 병렬 슬롯 데이에 정렬.
