## 안건 1. M0 집행 — 실 GPU 확인, PR #7 병합, 기본 품질 자동 결정

**임찬영:** "상태 보고서 기준으로 M0에 남은 건 사실상 세 줄입니다. ① 실제 GPU에서 `feat/render` 1회 완주 확인 ② INT-RENDER-013 리드 확정 문구 기입 ③ draft → Ready → merge commit 병합. 기술 blocker는 없고, mergeable clean에 CI success입니다. 측정 장비 제안 — 새 하드웨어 품의 내지 말고 **3차 대회의 때 대표님이 확보한 내장그래픽 노트북 2대**를 그대로 씁니다. 그 2대가 애초에 G1 게이트의 정의였으니, '목표 하드웨어 60fps'의 목표 하드웨어도 같은 물건이어야 계측의 연속성이 섭니다."

**정하늘:** "INT-RENDER-013은 실측에서 이상 없으면 제가 당일 확정 문구를 기입합니다. `startingCanyonLayout.ts`의 floorY −6 → −20은 상단 높이·통로 폭 불변이 재검증으로 확인됐으니, 실 GPU에서 심도 그레이딩 4구간이 의도대로만 나오면 사후 승인 사유가 완성됩니다. 일정 — **실측 D0(내일), 병합 D1.** 병합 후 dev는 '게임 로직 + 최종 아트'의 첫 통합 상태가 되고, 그 tip이 M1 전 창의 base입니다."

**임찬영:** "병합 방식 하나만 확정 — merge commit으로 하고, 커밋 메시지에 `[M0]` 태그와 측정 문서 경로를 답니다. 나중에 '언제 아트가 들어와서 fps가 어떻게 변했나'를 역추적하는 기준점이 이 커밋입니다."

## 안건 2. 규격 충돌 해석 — 어뢰 캠: 12차 "F 홀드" 대 16차 "발사 시 자동 전환"

**오세진:** "M3 앞머리 항목이지만 인터페이스에 걸리는 문제라 지금 짚습니다. 12차 대회의 결의 2는 어뢰 캠을 **'키 = F 홀드 + 어뢰 수명 동안만 노출되는 화면 버튼'**으로 규격화했습니다. 그런데 16차 결의 2-1은 **'발사 시 자동 전환, Space 복귀'**예요. 진입 방식이 정반대입니다. 게다가 16차 결의 2-2가 화면 버튼을 전면 제거했으니 12차의 '화면 버튼 진입점'은 존재 기반 자체가 사라졌고요. 어느 쪽이 정본입니까? 소회의는 대회의 결의를 개정할 수 없다는 원칙 때문에 제 선에서 못 정합니다."

**서지우 (배석 발언):** "절차 정리부터 — 이건 개정이 아니라 **충돌 해석**입니다. 동급 문서(대회의록)끼리 충돌하면 후행 결의가 선행 결의를 대체한다는 게 우리 문서 체계의 기본이고, 16차는 12차 이후입니다. 다만 후행 결의가 침묵하는 부분은 선행 결의가 살아 있어요. 그 경계를 개발팀이 오늘 그어주면, 제가 12차 결의 2에 폐지·존치 각주를 연결하겠습니다."

**정하늘:** "그럼 경계를 긋죠. 16차가 명시한 것 — 진입(자동 전환), 복귀 키(Space), 조종 불가, 캠 중 위협 사운드 유지. 이건 16차가 정본. 16차가 침묵한 것 — 12차의 **자동 복귀 조건 3종(① 잠수함 피격 ② 탐지 alert 전환 ③ 어뢰 명중·소멸·사거리 종료)**. 이건 충돌이 아니라 보완이므로 존치합니다. 16차의 '명중·빗나감 시 자동 복귀'는 3종 중 ③의 축약 표현으로 읽고, ①·②는 그대로 삽니다 — 애초에 alert 발화 지점은 15차에서 어뢰 캠 복귀 조건과 접속해두라고 상태 머신에 박아둔 그 자리입니다."

**임찬영:** "F 홀드와 화면 버튼은 명시적 폐기로 기록해주세요. 애매하게 남기면 누군가 F 키에 다른 기능을 못 붙입니다. 키맵 문서에서 F는 미배정으로 반환."

**오세진:** "그 해석이면 구현이 깔끔합니다. 진입은 `TorpedoFired` 이벤트 구독 한 줄, 복귀는 기존 3종 조건 + Space. 이의 없습니다."

> **결의 2:** 어뢰 캠 규격 충돌 해석 — 진입·복귀 키·조종 불가·사운드 유지는 **16차 정본**(발사 시 자동 전환, Space 복귀). 12차의 **자동 복귀 조건 3종은 보완 규격으로 존치**(16차의 '명중·빗나감 복귀'는 ③의 축약으로 해석). **F 홀드·화면 버튼 진입점은 명시적 폐기**, F 키는 키맵에서 미배정 반환. 12차 결의 2에 폐지·존치 각주 연결(서지우). 소회의 권한 = 해석, 개정 아님.

## 안건 3. 보스 본개발(M1) 창 범위표 — 5창

**정하늘:** "상설 규칙대로 범위표만 낭독·수락합니다. base는 M0 병합 후 dev tip. 보스 규격은 11차 결의 5(3단계 상태 머신 × 패턴 풀, 강체 4~5분절 계층 트랜스폼 애니, 물리 충돌체 캡슐 1개)와 16차 결의 1-3(**MVP 4패턴 봉인 — 돌진·투사체·약점 개방·최종 가속**, 소환·회전 근접은 부활 후보 1·2순위)입니다. 신규 알고리즘 0 원칙 유지."

### 창 1 — 리드 창 (정하늘)
- 보스 상태 머신: 3단계 × 4패턴 풀, 단계 전환 트리거(체력 임계 + 예고 동작 상태), `DestroyerAIController` 확장 계보 유지
- 패턴 4종 조립: 돌진(이동 코드 + 목표 벡터) / 투사체(어뢰 코드 역방향) / 약점 개방(피격 태그 전환) / 최종 가속(파라미터 배율)
- 단서 3개 → 보스 구역 개방 게이트 로직 (획득 자체는 창 2의 `InteractionSystem` 소비)
- 소환·회전 근접은 **스텁조차 금지** (3차 대회의 원칙 준용), 부활은 역순 아닌 지정순(소환 1순위)

### 창 2 — 게임플레이 창 (오세진)
- **[선행, 보스 착수 전]** `InteractionSystem` — E 키 근접 프롬프트, 2초 홀드 회수, **회수 중 소음 발생**(기존 `attachNoiseSource` 경로에 소음원 추가), 대상 타입: 금괴·salvage·단서·심층 지점 공용 (16차 결의 2-4, M2 배관 겸용, 1.5일)
- 약점 활성 상태·판정 소유 (11차 경계: 판정 = 세진, 연출 = 유리)
- **[병렬]** 파밍 보상 경제 배관 — 기존 단일 재화 지급, 해역당 상한 = 전투 보상 평균의 40%(`params/economy.json` 행, 튜닝표 등재)
- **[병렬]** 소나 스코프 판정 로직 1.5일 — 패시브(소음원 방위·번짐) + 액티브 핑(3초 전체 표시, 탐지 게이지 상승·쿨다운)
- **[완주 판정 직후, 같은 스프린트]** 침묵 항행 연결 1일 — 토글 키, 속도 상한 30%, 소음 계수 0.2, 산소 1.5배, 전부 params. `C_SILENT_RUNNING_INTERACTIVE=true` 전환, `attachSilentRunningSource` 조립 1줄 + 토글 입력 정의

### 창 3 — 그래픽스 창 (남유리)
- **[1주차 스파이크]** 보스 분절 애니 — 강체 4~5분절(머리·몸통·꼬리·턱·지느러미) 사인파 계층 트랜스폼, 1.5일. 실패 판정 시 B안(이동 곡선·카메라 연출, 0.5일) 전환 — 판정 기준: "위협적인가, 우스운가" 팀 4인 관찰
- 약점 발광·단계 전환 연출 (침묵 연출 접합부는 창 4의 BGM 배관과 접속)
- 보스 전장 밀도 — **신규 추가 금지, 기존 배치 예산 내 재배분** (11차 결의 1 원칙), M0 기준선(`M0_gpu_baseline.md`) 대비 드로우 증분 상한 기록
- **[병렬]** 스코프 렌더 0.5일 — 좌상단 다이제틱 원형 스코프, 화면 높이 18% 이하, 테두리 상태색 3종

### 창 4 — 빌드·툴 창 (임찬영)
- M0 실측·품질 자동 결정 기록 (안건 1)
- **[병렬]** 핑 쿨다운·탐지 게이지 상승 배관 0.5일, 스코프 테두리 상태색 이관(상단 텍스트 바 폐지 포함)
- **폭뢰 lifecycle 이벤트 발행** — `depthChargeEnteredWater`/`depthChargeExploded`를 `DepthChargeRunSystem`에서 발행 (계약 선언만 있고 production 발행자 0건인 상태 해소, 안건 4에서 상세)
- 침묵 항행 BGM 제거·심장박동 배관 (준호 님 세트 수신 시), 보스 음악·침묵 전환 배관 (11차 이월)
- **[병렬 슬롯]** B7 오인 사격 로깅 실측 — 기획 주관 세션과 정렬 (15차 결의 6)

### 창 5 — 통합 창 (정하늘)
- 병합 순서: `InteractionSystem` → 보스 코어(창 1+2 약점) → 병렬 2건(보상·스코프) → **회색 상자 완주 판정** → 침묵 항행 연결 → 침묵 포함 상태로 보스 밸런스 튜닝 → M1 봉인
- 완주 판정 전 보스 브랜치의 dev 병합 금지 원칙은 이번엔 반대로 적용 — **완주 판정 자체가 dev 통합 빌드에서 수행** (15차 판정 규칙 준용)

**남유리:** *(이의 1건)* "일정 이의입니다. M0가 D0~D1이면 제 스파이크는 D2 착수인데, 스파이크는 판정까지 1주차 말이라 하루가 아쉽습니다. `dev ⊆ feat/render`이고 PR #7이 mergeable clean이니, **feat/render를 base로 오늘 스파이크 브랜치를 따는 건** 사실상 미래의 dev 위에서 시작하는 겁니다. 14차의 '미확정 계약 위 선행 구현 금지'에 안 걸린다고 봅니다 — render 계약은 확정이고 병합만 남았으니까."

**정하늘:** *(반대)* "논리는 맞는데 구멍이 하나 있습니다. M0 실측에서 문제가 나오면요? 실측은 형식 절차가 아니라 진짜 게이트입니다. 텍스처가 실 GPU에서 깨지거나 medium이 40fps가 나오면 feat/render에 수정 커밋이 붙고, 그 위에 딴 스파이크 브랜치는 리베이스 대상이 됩니다."

**남유리:** "그 리스크는 제가 삽니다 — 분절 애니는 씬 그래프 회전만 쓰는 작업이라 render 수정과 충돌할 파일이 사실상 없어요. **조건부로 받죠: 실측 발 수정으로 리베이스가 필요해지면 그 비용은 그래픽스 창이 전액 부담하고, 리드 창 일정에 전가하지 않습니다.**"

**정하늘:** "비용 소유가 명시되면 원칙 위반이 아니라 위험 인수네요. 조건부 승인. 단 병합은 어떤 경우에도 M0 병합 후 dev 기준."

> **결의 3:** 5창 범위표 확정(상기). 보스 = 3단계 × 4패턴(돌진·투사체·약점 개방·최종 가속), 소환·회전 근접 스텁 금지·부활 후보 1·2순위. `InteractionSystem` 선행, 보상·스코프 병렬, 침묵 항행은 완주 판정 직후 같은 스프린트 연결 후 밸런스 튜닝. 분절 애니 스파이크는 feat/render base 선행 착수 **조건부 허용**(리베이스 비용 그래픽스 창 전액 부담, 병합은 M0 후 dev 기준).

## 안건 4. 병렬 편입 2건의 접합면 — 스코프 입력 계약과 침묵 항행 순서

**오세진:** "설계 확정 전에 순서 모순 하나 검사합니다. 16차 스코프 규격에 '패시브 스코프는 내 소음이 클수록 노이즈가 끼고, **침묵 항행 시 가장 선명**'이 있습니다. 그런데 침묵 항행 연결은 완주 판정 '직후'예요. 스코프를 병렬로 먼저 만들면 침묵 항행 없는 세계 기준으로 만드는 건데, 이거 이준호 님이 16차에서 경고한 '밸런스 두 번 잡기'의 재판 아닙니까?"

**정하늘:** "구현 계약으로 풀립니다. 스코프 노이즈를 '침묵 항행 여부'라는 불리언에 묶지 말고, **탐지 시스템이 이미 계산하는 내 소음 계수의 함수**로만 정의하세요. 침묵 항행이 연결되는 순간 소음 계수에 0.2가 곱해지고, 스코프는 코드 변경 0으로 자동으로 선명해집니다. 스코프는 침묵 항행의 존재를 몰라야 합니다."

**오세진:** "소비자를 계수에 묶고 정책은 상류에. 수용합니다 — `SonarScopeReadModel`은 `noiseFactor` 하나만 받는 걸로 계약서에 적죠. 모순 해소."

**임찬영:** *(이의 1건)* "제 쪽 접합면 — 폭뢰 lifecycle 이벤트요. 상태 보고서대로 `depthChargeEnteredWater`·`depthChargeExploded`는 계약 선언만 있고 발행자가 0건입니다. 원래 '사운드 배선 시점에'라고 미뤄뒀는데, 이번에 패시브 스코프가 소음원 방위를 표시하게 되면 질문이 생깁니다 — **낙하 중인 폭뢰는 스코프에 찍힙니까?** 찍히면 '풍덩 소리 듣고 3초 세는' 회피 문법이 시각으로 복제되는 거라, 1차 본회의 사운드 헌법 위반 소지가 있어요. 그런데 준호 님이 오늘 안 계십니다."

**정하늘:** "결정 권한 분리로 갑니다. 개발팀이 오늘 정할 수 있는 건 배관까지 — **발행자는 이번에 만듭니다.** 스코프 표시 여부는 개발 결정이 아니라 게임 룰이니, `params`에 `depthChargeOnPassiveScope` 불리언으로 빼고 **초기값 false**(찍히지 않음 — 사운드 헌법의 보수적 해석)로 둡니다. 기획·사운드가 true로 뒤집고 싶으면 튜닝표 행을 추가해서 대회의 없이 뒤집을 수 있고요. 우리는 스위치를 만들고, 스위치의 방향은 소유자에게."

**임찬영:** "발행은 이번, 정책은 params, 초기값은 보수적으로. 깔끔합니다. 철회합니다. 겸사겸사 이 이벤트가 붙으면 폭뢰 입수·폭발 사운드 트리거(현재 미배선)도 같은 발행 지점에서 공짜로 해결됩니다."

> **결의 4:** 스코프 입력 계약 = `noiseFactor` 단일 의존(침묵 항행 비인지) — 침묵 연결 시 코드 변경 0으로 자동 반영, 이중 밸런스 작업 원천 차단. 폭뢰 lifecycle 이벤트는 이번 스프린트에 **발행자 구현**(`DepthChargeRunSystem` 입수·폭발 시점), 패시브 스코프 표시 여부는 `params.depthChargeOnPassiveScope` **초기값 false**(사운드 1차 정보 원칙의 보수적 해석), 변경 권한은 기획·사운드의 튜닝표 행 추가로 위임. 사운드 트리거 배선도 동일 발행 지점 활용.

## 안건 5. 일정·완주 판정·리스크

**정하늘:** "일정 골격 — M0 D0~D1 / 선행 `InteractionSystem` D2~D3 / 보스 코어 + 병렬 2건 D2~D9 / **회색 상자 완주 판정 D10** / 침묵 항행 연결 D11 / 침묵 포함 밸런스 튜닝 D12~D13 / M1 봉인 D14. M3 앞머리(어뢰 캠 1일 + 버튼 제거·프리룩 1일)는 M1 봉인 후 별도, 오늘 범위 밖.

**완주 판정(Exit Criteria):** 통합 dev 빌드에서 — 출항 → 파밍·전투로 재화 획득 → 단서 3개 회수(E 키) → 보스 구역 개방 → 3단계 4패턴 상대로 격파 **및** 파괴 양쪽 경로 각 1회 완주 → 정산·재출항. 회색 박스 보스여도 무방, 분절 애니는 판정 조건 아님(스파이크 별도 판정). 스코프로 보스 방위·약점 타이밍이 읽히는지 확인 포함.

**리스크 3종 —**
- **R-M1. 분절 애니 스파이크 실패** (1주차 말 판정) → B안 전환 0.5일, 유리 님 잔여 시간은 약점·전환 연출 품질로 (11차 확정 경로 유지)
- **R-M2. M0 실측 미달(medium 60fps 실패)** → 기본 low 확정 + 근거 기록으로 M0는 그대로 진행(재회의 불요, 16차 결의 1-2). 단 보스 전장 드로우 증분 상한을 low 기준으로 재산정, 유리 님 창에 통보
- **R-M3. D10 완주 판정 실패** → 비상 컷: 4패턴 → 2패턴(돌진·투사체)으로 축소, 약점 개방·최종 가속은 판정 재도전 시 복원. 발동 권한 리드 단독 (11차 R-P3 계보)"

**오세진:** "R-M3에 한 줄만 — 2패턴 축소 시에도 **약점 '판정' 코드는 남기고 '패턴' 노출만 끕니다.** 판정은 스코프 액티브 핑의 약점 표시와 얽혀 있어서 뜯으면 스코프까지 무너집니다. 컷은 노출 플래그로."

**정하늘:** "동의, 컷 = 플래그 오프로 기록. 이견 없으면 낭독 수락으로 마칩니다."
