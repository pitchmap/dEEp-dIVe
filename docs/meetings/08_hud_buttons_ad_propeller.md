# 프로젝트 "딥 다이브(가제)" 화면 버튼·A/D 프로펠러 입력 소회의록 — 요약 재구성본

> **문서 성격:** 원문 대화록이 보존되지 않아, 리드 계약 커밋(`b69890b`,
> INT-CORE-002 — 요청 사유에 본 소회의가 명시됨)과 각 파트 구현 커밋
> (`218ad86`·`383f257`·`e0f7609`·`2f8b66f`)에서 **결정 사항만 역추적해
> 재구성한 요약본**이다. 발언 원문이 아니며, 원문 확보 시 교체한다.
> 안건 번호는 커밋·INTEGRATION_NOTES에 남은 표기(S7·S9)를 따른다 —
> 나머지 안건의 원 번호는 미상.

**일시:** D+5 플레이테스트 리뷰(07) 직후 소회의
**참석:** 개발 리드 / 게임플레이 / 그래픽스 / 빌드·툴 (입력·표현 경계 조정)
**주제:** ① PC 화면 전투 버튼(HUD) 도입 방식 ② A/D 선회와 프로펠러
회전의 관계 ③ 축·선수/선미 규약 통일

---

## 결의 사항

### 결의 1 — PC 화면 조준·발사 버튼 도입, 단 **전투 입력 경로는 하나**

- 우하단 반투명 소형 버튼으로 조준·발사를 제공한다 (마우스 없는·마우스
  익숙지 않은 테스터 대응).
- **별도 전투 시스템 금지:** 마우스와 화면 버튼은 **동일 `AimSystem`
  인스턴스의 동일 메서드**(beginAim/endAim/fireTorpedo)를 호출한다.
  판정·재장전·잔량이 두 경로에서 완전히 동등해야 한다.
  → 계약화: INT-CORE-002 (`AimSystem` + `aimModeChanged` 이벤트).
- 버튼 배선은 composition root(Game)에서만 잇는다. UI는 게임플레이
  구현체를 import하지 않고 계약 단면만 본다.
- 마우스 조준 3회 이상 관측 시 버튼 존재감 축소 (기준은 `params/ui.json`).

### 결의 2 (S7) — 프로펠러 회전은 **실제 전후 속도만** 입력받는다

- 선미(+Z) 프로펠러 1개. 전진 = 정회전, 후진 = 역회전 — 입력은
  **부호 있는 전후 속도** 하나뿐이다.
- **A/D 단독 입력(선회)은 프로펠러 회전에 무영향** — 규약 함수
  `conventions.propellerSpinRatio(speed, …)`의 시그니처(속도만 입력)로
  강제한다.
- 정지 시 최대 회전의 8% 공회전 [초기 테스트값] — 수치는
  `params/movement.json propellerIdleSpinRatio`(0~1 검증) 단일 소스.
  코드·렌더 설정 파일에 복제하지 않는다.
- 프로펠러 최대 각속도(rad/s)는 렌더 연출 상수 — 밸런스 수치가 아니므로
  파라미터화하지 않는다 (리드 결정).

### 결의 3 (S9) — 정지 상태 제자리 선회 유지

- 속력 0에서도 A/D 선회는 동작한다 (D+5 빌드 동작 유지). 이때 프로펠러는
  공회전만 한다 (결의 2와 일관).

### 결의 4 — 축·선수/선미 규약의 코드화

- **로컬 -Z = 선수, +Z = 선미, 월드 +Y = 위**를 `src/core/conventions.ts`
  하나로 코드화한다 (`bowDirectionXZ`·`sternDirectionXZ`·`meshYawRadians`·
  카메라 리센터 규약). 파트별 숫자·벡터 복제 금지.
- Space 리센터 후방 뷰 = **선미 뒤쪽 상단에서 선수 방향을 보는 시점** —
  리센터 시 프로펠러가 카메라 가까이 보인다.
- *(후속 각주)* 최초 규약 `cameraRecenterYawRadians`는 시선/위치 오프셋
  이중 해석 문제가 확인되어 INT-CORE-004(`c4841cf`)에서 폐기,
  `cameraRecenterOffsetDirectionXZ`(카메라 위치 = 선미 방향)와
  `cameraRecenterLookDirectionXZ`(시선 = 선수 방향)로 분리 확정.
  검증 기준: 리센터 시 프로펠러가 카메라 가까운 쪽, W 전진 시 화면 안쪽.
- 기존 D+5 구현(전진 벡터·mesh.rotation.y·CameraRig 배치)과 동일 정의 —
  동작 변경 없음, 규약·계약 추가만.

### 결의 5 — 조작 안내·Pointer Lock (빌드·툴 소관)

- 좌측 조작 안내 패널: 키 바인딩 단일 소스(`controlsConfig.ts`)에서 생성,
  H 토글로 화면 버튼과 함께 숨김·복원.
- Pointer Lock: 캔버스 클릭 진입(발사 아님), Esc 해제 → 일시정지(기존
  GameLoop 정지 재사용, 새 상태 추가 없음), 진입 직후 250ms 입력 무시,
  게임 중 우클릭 컨텍스트 메뉴 방지.
- 입력 계측: 마우스/버튼별 조준·발사 횟수·첫 발사 요청 시각(G3 참고)을
  게이트 기록에 합류.
