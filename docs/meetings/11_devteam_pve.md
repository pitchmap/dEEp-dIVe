3. **인스턴싱 밀도 계측** — 통과. 어군 2종 + 산호 재배치 상태에서 58~61fps. 단, 보스 구역에 밀도를 더 얹을 여유는 **없습니다.** 6차에서 결의된 보스 전장의 엄폐물은 신규 추가가 아니라 기존 배치 예산 안에서 재배분해야 합니다."

**남유리:** "3번 단서는 제 파트에 직결되니 기록 요청합니다 — 보스 전장 데코는 '추가'가 아니라 '이동'이다."

> **결의 1:** 조건부 3건 종결 — 조준경 확정 / Ctrl+W 이중 대응 유지 / **보스 전장 밀도는 기존 예산 내 재배분 원칙** 기록.

## 안건 2. PvE 전환 아키텍처 — "이월이냐 재작성이냐"

**오세진:** *(강한 반대 예고)* "6차 회의에서 하늘 님이 '뒤집힌 건 틀이지 내용물이 아니다'로 기획을 설득하셨는데, 코드 현실은 다릅니다. 지금 게임 상태 머신은 `시작 → 세션 → 사망/클리어 → 결과` 딱 네 상태예요. 세션 서바이벌 전제가 **상태 머신의 등뼈**에 박혀 있습니다. 여기에 기지·출항·귀환·상점·저장을 덧붙이면 분기 지옥이 됩니다. 저는 상태 머신 **전면 재작성**을 요구합니다. 2일이면 합니다."

**정하늘:** *(반대)* "전면 재작성 2일은 낙관 추정이고, 진짜 비용은 그 뒤에 옵니다 — 재작성하면 검증된 전투 코어(이동·어뢰·탐지·AI)를 새 구조에 다시 붙이면서 회귀 버그를 전수 테스트해야 해요. 우리가 기획에 '이월'을 판 근거가 '검증됐다'인데, 재작성은 그 검증을 스스로 무효화하는 겁니다."

**오세진:** "그럼 반대로 물을게요. 지금 상태 머신에 기지·상점을 덧붙이는 안의 진짜 이름이 뭡니까? 기술 부채입니다."

**정하늘:** "둘 다 아닌 세 번째 안으로 가르죠. **상태 머신을 2계층으로 분리**합니다 — 상위 `메타 루프`(기지 → 출항 준비 → 해역 → 귀환 정산 → 기지)는 신규 작성, 하위 `해역 세션`은 기존 상태 머신을 **그대로** 하위 상태로 포장(wrap)합니다. 기존 코드는 '해역 안에서 벌어지는 일' 전담으로 한 줄도 안 건드리고, 세진 님이 원하는 깨끗한 구조는 상위 계층이 가져갑니다. 신규 작성 1일 + 포장 0.5일."

**오세진:** "…하위를 안 건드린다는 보장만 있으면 좋은 절충입니다. 조건 — 상하위 간 통신은 이벤트 3종(세션 시작 / 세션 결과 / 중도 귀환)으로만 제한하고, 상위가 하위 내부 상태를 직접 읽는 것 금지. 이 경계가 무너지면 결국 한 덩어리가 됩니다."

**정하늘:** "그건 반대할 이유가 없는 설계죠. 채택. 같은 원리로 세력 구분도 — 적대/중립/경비함은 클래스 분화가 아니라 기존 함선 개체에 **Faction 태그 + 드롭 테이블 참조** 두 필드만 추가합니다. 경비함 = 구축함 AI에 태그와 스폰 조건만 얹은 것, 6차에서 약속한 0.5일 그대로."

> **결의 2:** 상태 머신 **2계층 분리** — 상위 메타 루프 신규(1일), 하위 해역 세션은 기존 코드 무수정 포장(0.5일). 계층 간 통신은 이벤트 3종으로 제한, 상위의 하위 내부 접근 금지. 세력 시스템은 Faction 태그 + 드롭 테이블 방식(재작성 없음). 전면 재작성안 기각.

## 안건 3. 저장 시스템 — 싱글 게임의 세이브는 어디까지 지키나

**임찬영:** "6차 결의 7을 받는 파트입니다. 저장 매체는 브라우저 로컬 저장으로 충분한데, 세 가지를 결정해야 합니다.

첫째, **스키마 버전.** 업데이트마다 저장 구조가 바뀔 텐데 버전 필드 없이 시작하면 첫 패치에서 전 유저 세이브가 깨집니다. 버전 필드 + 마이그레이션 함수 틀만 지금 넣죠. 0.5일.

둘째, **손상 대응.** 브라우저 저장은 유저가 캐시를 지우면 사라지고, 쓰기 도중 탭이 닫히면 깨질 수 있습니다. 이중 슬롯(직전 저장 백업 유지)을 제안합니다. 0.5일.

셋째, **치트.** 로컬 저장은 개발자 도구로 누구나 열어서 크레딧을 백만으로 고칠 수 있습니다. 암호화나 체크섬을 넣을지."

**오세진:** *(반대 1건)* "셋째에 반대합니다. 싱글 오프라인 게임에서 세이브 조작은 치트가 아니라 **유저의 자유**입니다. 리더보드도 PvP도 없는데 누구에게서 뭘 지킵니까? 체크섬 넣어봤자 뚫리는 데 하루고, 우리는 그 하루가 아까운 팀이에요. 스코프 가드 정신으로 기각합시다."

**임찬영:** "…방어할 대상이 없다는 건 맞네요. 철회합니다. 대신 첫째·둘째는 사수합니다 — 이건 치터가 아니라 **선량한 유저의 세이브**를 지키는 겁니다."

**정하늘:** "버전 필드와 이중 슬롯은 나중에 넣으면 열 배 비싸지는 종류라 지금이 맞습니다. 채택. 저장 시점은 6차 결의 7 그대로 — 기지 귀환 시 확정 저장, 희귀 부품은 획득 즉시 저장. 그 외 자동 저장은 없음(귀환의 긴장을 지키는 게 기획 의도니까)."

> **결의 3:** 로컬 저장 채택. **스키마 버전 필드 + 마이그레이션 틀, 이중 슬롯 백업** 포함(합계 1일). 체크섬·암호화 기각 — 싱글 오프라인에서 세이브 조작은 유저 자유로 규정. 저장 시점 = 귀환 확정 + 희귀 부품 즉시, 그 외 자동 저장 없음.

## 안건 4. 업그레이드 = 파라미터 배율 레이어

**정하늘:** "6차 설득의 핵심 문장 — '업그레이드는 파라미터에 배율 곱하기' — 를 실제 구조로 확정합니다. 원칙: **params JSON 원본은 불변.** 업그레이드는 원본을 수정하지 않고, 런타임에서 `최종값 = 기준값 × (1 + 보정 합)` 레이어를 통과시킵니다. 태현 님의 튜닝표 커밋 권한과 유저의 성장 데이터가 같은 파일을 두고 싸우면 안 되니까요."

**오세진:** "수식에 이견 하나 — 곱연산 스택(×1.1 ×1.1…)이 아니라 **합연산**(+10% +10% = +20%)으로 갑시다. 곱연산은 항목이 쌓일수록 기하급수라 밸런스 예측이 안 되고, 태현 님이 튜닝표에서 '업그레이드 5단계면 총 +50%'처럼 암산할 수 있어야 튜닝 사이클이 빨리 돕니다."

**임찬영:** "찬성 + 툴 하나 얹겠습니다. JSON 핫리로드 툴에 **'업그레이드 시뮬레이터' 모드** — 업그레이드 조합을 체크박스로 켜고 최종 수치를 미리 보는 화면. 기존 툴 확장이라 0.5일이고, 태현 님이 밸런스를 빌드 없이 검증할 수 있게 됩니다."

**서지우 (배석 발언):** "기획 접점 확인 — 그 시뮬레이터 화면을 튜닝표 v3의 '테스트 결과' 열 증빙으로 쓰도록 기획팀에 전파하겠습니다. 그리고 6차 결의의 신 스코프 가드(업그레이드 7항목)를 params 스키마 차원에서도 강제할 수 있습니까?"

**정하늘:** "가능하고 좋은 요청입니다 — 업그레이드 정의 파일에 항목이 8개 이상이면 빌드가 경고를 내게 하죠. 가드를 문서가 아니라 도구가 지키게."

> **결의 4:** params 원본 불변 + 런타임 배율 레이어. 스택은 **합연산**(밸런스 암산 가능성 우선). 핫리로드 툴에 업그레이드 시뮬레이터 추가(0.5일). 신 스코프 가드(7항목)를 빌드 경고로 기계 강제.

## 안건 5. 보스 구현 — "통짜 강체"의 기술 정의

**정하늘:** "6차 결의 6의 '통짜 강체'를 구현 언어로 못 박습니다. AI는 제 파트 — 구축함 2상태 머신을 확장해 **보스 상태 머신: 3단계 × 단계별 패턴 풀**로 갑니다. 패턴 6종은 전부 기존 부품 조합입니다: 돌진 = 이동 코드 + 목표 벡터, 투사체 = 어뢰 코드 역방향, 회전 근접 = 충돌 판정 + 회전, 소환 = 어군 인스턴싱 + 소형 적 AI, 약점 개방 = 피격 판정 태그 전환, 최종 가속 = 파라미터 배율. 신규 알고리즘 0."

**남유리:** *(강한 반대)* "렌더 쪽은 그렇게 낙관 못 합니다. '통짜 강체'를 문자 그대로 받으면 보스가 **돌덩이처럼 미끄러지는** 그림이 나와요. 거대 생물의 위협감은 절반이 움직임입니다 — 몸통이 굽고, 입이 벌어지고, 지느러미가 젓는. 저는 최소한의 스켈레탈 애니메이션(본 8~10개)을 요구합니다. 이게 없으면 세라 님이 그린 '군함을 잡아먹은 놈'이 게임에선 '군함 모양 바위'가 됩니다."

**정하늘:** "스켈레탈은 두 가지가 걸립니다. 스키닝 연산이 내장그래픽 예산을 건드리고, 애니메이션 파이프라인(리깅·익스포트·재생 시스템)이 우리 스택에 처음 들어오는 신규 인프라예요. 공수 추정 4일 + 성능 리스크."

**남유리:** "그럼 절충안 — 스키닝 없는 **계층 트랜스폼 애니메이션**으로 깎겠습니다. 보스를 강체 4~5개 조합(머리·몸통·꼬리·턱·지느러미)으로 나누고, 각 부위를 사인파 회전으로 흔듭니다. 스키닝 0, 본 시스템 0, 기존 씬 그래프 회전만 씁니다. 로우폴리 플랫 셰이딩에서는 오히려 이 '기계적으로 굽는' 움직임이 아트 스타일과 맞고요. 공수 1.5일."

**정하늘:** "강체 '조합'은 통짜 정신 위반이 아닌가… 아니, 아닙니다. 6차 결의가 금지한 건 관절 **물리**(촉수 체인)지 시각 분절이 아니죠. 물리 충돌체는 여전히 캡슐 하나, 시각만 4~5분절. 채택. 단, 세라 님 X-ray 때처럼 **1주차 스파이크로 판정**합니다 — 흔들리는 보스가 위협적인지, 우스운지."

**남유리:** "스파이크 수용. 판정 실패 시 대체안까지 지금 정하죠 — 부위 애니메이션을 포기하고 **이동 곡선과 카메라 연출**(급가속·관성·근접 시 화면 흔들림)로 위협감을 내는 B안. 이관 공수 0.5일."

**오세진:** "게임플레이 접점 하나 — 약점 개방(패턴 4)은 제 피격 판정과 유리 님 시각 표현이 한 몸입니다. 경계를 지금 긋죠: **약점의 활성 상태와 판정은 제 소유, 활성 시 발광·개방 연출은 유리 님 소유.** 오디오 배관 때처럼."

> **결의 5:** 보스 AI = 기존 부품 조합의 3단계 상태 머신(신규 알고리즘 0). 렌더 = 스켈레탈 기각, **강체 4~5분절 계층 트랜스폼 애니메이션**(1.5일) — 물리 충돌체는 단일 캡슐 유지로 '통짜' 결의 준수. 1주차 스파이크 판정, 실패 시 이동 곡선·카메라 연출 B안(0.5일). 약점 = 판정(오세진) / 연출(남유리) 경계 확정.

## 안건 6. 파트 분담과 일정 — 6차 4단계의 개발 번역

**정하늘:** "6차 안건 10의 4단계를 20영업일로 번역합니다. 원칙은 지난번과 동일 — 조작보다 계측이 먼저였다면, 이번엔 **콘텐츠보다 루프가 먼저.** 보스가 없어도 '출항-파밍-귀환-강화'가 도는 빌드를 최우선으로 만듭니다."

| 단계 | 내용 | 기간 | 완료 판정 (Exit Criteria) |
|---|---|---|---|
| **1. 이월·개조** | 2계층 상태 머신, Faction 태그·드롭, 경비함 전환, 재화 획득 | D1~D4 | 화물선을 부수면 크레딧이 뜨고 획득되는 빌드 |
| **2. 성장 루프** | 기지 화면, 저장(버전+이중 슬롯), 업그레이드 배율 레이어, 장비 슬롯, 시뮬레이터 툴 | D5~D9 | **출항→파밍→귀환→강화→재출항이 저장 포함 완주 가능.** D+9 빌드 = 이것 |
| **3. PvE 콘텐츠** | 해저 보물(부순다/줍는다), 단서 3종, 보스 본체·3단계·보상, 손실 페널티 | D10~D16 | 튜토리얼부터 보스 격파까지 30~60분 1회 완주. D+16 빌드 |
| **4. 연출·봉인** | 보스 애니·침묵 전환·전용 음악 연동, 외형 반영(선체·주무장), 저사양 검증, 데모 봉인 | D17~D20 | 60fps 유지 + 6차 결의 전 항목 체크리스트 통과. D+20 = 데모 제출본 |

| 담당 | 파트 | 주요 산출물 | 의존 관계 |
|---|---|---|---|
| **정하늘 (리드)** | 메타 루프·보스 AI·통합 | 2계층 상태 머신 상위, 보스 상태 머신·패턴 6종, 단계 통합 | 전 파트 |
| **오세진 (게임플레이)** | 전투 개조·경제·약점 판정 | Faction·드롭 테이블, 해저 보물 판정, 손실 페널티, 약점 활성 판정, 장비 4종 로직 | 태현 님 경제 수치표(D+3, 이번에도 절대 마감) |
| **남유리 (그래픽스)** | 보스 렌더·기지 씬·외형 반영 | 보스 분절 애니(1주차 스파이크), 약점·단계 전환 연출, 기지 화면 배경, 선체·주무장 외형 3단계 | 세라 님 보스 모델(상대 마감: 시안 확정 + 5일) |
| **임찬영 (빌드·툴)** | 저장·툴·오디오 배관 | 세이브 시스템(버전·이중 슬롯), 업그레이드 시뮬레이터, 보스 음악·침묵 전환 배관, 스코프 가드 빌드 경고 | 준호 님 보스 사운드 세트(상대 마감: 패턴 확정 + 4일) |

**임찬영:** "의존성 마감은 3차 대회의 결의대로 전부 상대 표기로 받았고, 이번 병목도 명시하죠 — **태현 님 경제 수치표 D+3.** 크레딧 드롭량·업그레이드 비용·손실률이 없으면 2단계 Exit Criteria를 검증할 수 없습니다."

**서지우 (배석 발언):** "병목 지정 접수. 태현 님에게 오늘 중 전달하고, 지연 시 책임 소재는 지난 R-D2 규칙(임시값 선진행, 책임은 지연 쪽)을 그대로 적용하겠습니다."

> **결의 6:** 4단계 20일 일정·Exit Criteria 확정, 주간 빌드 D+9(성장 루프)·D+16(전체 완주)·D+20(데모 봉인). 4인 파트표 확정, 의존성 상대 마감, 병목 = 경제 수치표 D+3 절대 마감. 버스 팩터 1 금지·주 2회 워크스루 유지.

## 안건 7. 저장소 규칙 갱신과 리스크 합의

**임찬영:** "구조 변경에 맞춰 규칙 갱신 제안 —
- 디렉터리 추가: `/src/meta`(기지·저장·상점·업그레이드) / `/src/systems/economy`(드롭·손실) / `/params/upgrades.json`, `/params/economy.json`(태현 님 직접 커밋 범위 확장)
- 커밋 태그 확장: 게이트 태그 [G1~G9]에 더해 **[LOOP](성장 루프) [BOSS] [ECON](경제)** — 데모 리뷰 때 '언제 뭐가 바뀌어 밸런스가 무너졌나' 역추적용
- 세이브 스키마 변경 커밋은 마이그레이션 함수 동반 필수, 미동반 시 리뷰 반려
- 나머지(3브랜치, dev 무결성, 주간 빌드일 main 머지)는 기존 유지"

**오세진:** "이견 없음. 스키마-마이그레이션 동반 규칙은 특히 좋네요 — 세이브 깨먹은 커밋을 코드 리뷰 단계에서 잡는 거니까."

**정하늘:** "마지막, 리스크 4종과 대응 경로를 합의하고 끝냅니다.

- **R-P1. 보스 분절 애니 스파이크 실패** (1주차 말 판정) → B안(이동 곡선·카메라 연출) 전환, 유리 님 0.5일 이관 — 안건 5에서 확정
- **R-P2. 경제 수치표 D+3 지연** → 임시 기본값 선진행, 책임은 지연 쪽(R-D2 준용), 튜닝 일정만 후퇴
- **R-P3. D+16에 보스전 미완** → 비상 컷: 보스 패턴 6종 → 4종(돌진·투사체·약점·가속)으로 축소, 소환·회전 근접 컷. 발동 권한 리드 단독
- **R-P4. 성장 루프가 '재미없다'로 판정** (D+9 빌드 리뷰) → 이건 개발이 아니라 기획 리스크로 즉시 이관 — 수치 튜닝으로 풀되, 구조 변경 요구는 대회의 소집 사안"

**전원:** 이견 없음.

> **결의 7:** 디렉터리·태그·세이브 규칙 갱신 / 리스크 4종 대응 경로 사전 확정, R-P3 비상 컷은 리드 단독 권한, R-P4는 기획 이관 사안으로 분류.
