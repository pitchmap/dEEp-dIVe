# M0_gpu_baseline — 그래픽 통합 성능 기준선 (빌드·툴 판)

> ⚠ **같은 경로가 두 역할 브랜치에 존재한다. 이 파일을 그래픽스판으로
> 덮어쓰거나 삭제하지 말 것 — 최종 선택은 통합 관리자 몫이다.**
>
> | 판본 | 위치 | 내용 |
> |---|---|---|
> | **그래픽스판** | `origin/feat/render:docs/measurements/M0_gpu_baseline.md` (89줄) | 측정 **절차 규격**(60초 시나리오·드로우 콜·GPU 메모리·404 fallback), 실기기 표(빈 칸 = 미실측), 기본 품질 판정 규칙 |
> | **빌드·툴판** | 이 파일 | 컨테이너 **참조 실측치**, 환경·GPU 기록, 소프트웨어 렌더러 식별, 툴링 미실시 항목 |
>
> **두 판본은 모순되지 않는다.** 양쪽 다 ① 실기기 측정은 미실시 ②
> SwiftShader는 GPU 증적 아님 ③ 기본 품질 결정 보류로 같은 결론이다.
> 그래픽스판은 '어떻게 재는가', 빌드·툴판은 '무엇이 실제로 측정됐는가'를
> 담고 있어 **병합하면 서로를 채운다.** 통합 시 그래픽스판의 §A 절차·§B
> 실기기 표를 정본으로 두고 이 문서의 §3 환경·참조 측정을 부록으로 붙이는
> 방식을 권고하되, 결정은 통합 관리자가 한다.

> 실행: `node scripts/measure-m0.mjs` (원자료 `docs/measurements/m0-measurement.json`).

## 1. M0 인수 조건과 이 문서의 위치

M0 인수는 '내장그래픽 노트북 2대 × low/medium/high × 3개 시나리오' 실측을
요구한다. 이 문서는 그 표의 **틀과 컨테이너 참조값**을 제공하고, 하드웨어
열은 실제 노트북을 가진 창이 채운다.

## 2. 하드웨어 실측 — 미실시 (환경 제약)

**빌드·툴 창은 내장그래픽 노트북 2대를 측정할 수 없다.**
실행 환경이 헤드리스 리눅스 컨테이너이며 물리 GPU·노트북이 없다.
이 항목은 **미실시로 남기고 위장하지 않는다.**

| 요구 | 상태 |
|---|---|
| 노트북 A (내장그래픽) 실측 | ⛔ **미실시** — 하드웨어 없음 |
| 노트북 B (내장그래픽) 실측 | ⛔ **미실시** — 하드웨어 없음 |
| 그래픽스 창 수치와 교차 확인 | ⛔ **불가** — 대조할 상대 수치가 저장소에 없음 |

교차 확인은 그래픽스 창이 자기 측정값을 이 문서에 올린 뒤에만 가능하다.
현재 저장소에 그래픽스 창의 FPS 수치가 없어 대조 대상이 존재하지 않는다.

## 3. 컨테이너 참조 측정

### 3-0. 측정 환경 (자동 기록 — 모르는 값은 null, 0으로 적지 않는다)

| 항목 | 값 |
|---|---|
| OS | `linux 6.18.5-fc-v18 (x64)` |
| CPU | `Intel(R) Xeon(R) Processor @ 2.80GHz` × 4 |
| 브라우저 | `Chromium 141.0.7390.37` |
| GPU renderer | `ANGLE (Google, Vulkan 1.3.0 (SwiftShader Device (Subzero) (0x0000C0DE)), SwiftShader driver)` |
| GPU vendor | `Google Inc. (Google)` |
| GL | `WebGL 2.0 (OpenGL ES 3.0 Chromium)` |
| **소프트웨어 래스터라이저** | **감지됨** — 일치 패턴 `swiftshader` |
| **실제 GPU 증적** | **아니오** (`realGpuEvidence=false`) |

`WEBGL_debug_renderer_info` 사용 가능: True.
**SwiftShader는 실제 GPU 증적으로 인정하지 않는다** — 도구가 이를 자동
판별해 `M0_REAL_GPU_EVIDENCE_COMPLETE=false`를 출력하며, 사람이 바꿔 적을
여지를 두지 않았다.

### 3-2. 이 FPS는 tier 비교에 쓸 수 없다

프레임 간격이 66.7/83.3ms 같은 계단값에만 모여 있다 — 렌더 부하가 아니라
컨테이너 `requestAnimationFrame` 스로틀링이 만든 값이다. low와 high의
평균 차이가 1fps 안팎인데, 품질 단계는 파티클·림라이트·항법등·텍스처
상한·탐조등 빔·기포 풀을 전부 바꾸므로 정상 GPU라면 나올 수 없다.

| 읽을 수 있다 | 읽을 수 없다 |
|---|---|
| 세 tier 전부 부팅·로딩·루프 진입 성공 | tier 간 상대 성능 |
| 로딩 시간 | 절대 FPS·60fps 달성 여부 |
| **콘솔·페이지 오류 0건** (9/9) | 기본 품질 결정 근거 |

## 5. 17차 결의 대비 미실시 계측 항목

17차 안건 1(남유리)이 지정한 측정 항목 중 이번에 **하지 못한 것**:

| 항목 | 상태 |
|---|---|
| 드로우 콜 수(현재 65) 대조 | ⛔ 미실시 — 계측 훅 미배선 |
| 텍스처 404 fallback 미발동 확인 | ⛔ 미실시 |
| 폭뢰 피격·심해 하강 시나리오 | ⛔ 미실시 — 현재 시나리오는 기지 대기·항행·조준 3종 |
| medium 60fps 판정 | ⛔ **불가** — §3-1의 rAF 스로틀링으로 계측치가 판정 입력이 될 수 없음 |

17차는 '사람 판단 없이 계측치가 medium/low를 결정한다'고 정했다. 컨테이너
계측치는 그 입력 자격이 없으므로 **품질 기본값 결정을 내리지 않았다.**

## 6. 남은 것

1. **노트북 2대 실측** — 하드웨어 보유 창이 §3 표와 같은 형식으로 채운다.
   측정 절차는 `scripts/measure-m0.mjs`와 동일 시나리오·동일 tier를 쓰되,
   실제 GPU에서 돌려야 tier 비교가 성립한다.
2. **그래픽스 창 수치와 교차 확인** — 상대 수치 도착 후.
3. M0 통과 판정은 위 둘이 채워진 뒤 통합 관리자가 내린다. **이 문서만으로
   M0 성능 통과를 선언하지 않는다.**
