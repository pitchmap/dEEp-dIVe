# M0_gpu_baseline — 그래픽 통합 성능 기준선 (단일 정본)

> **이력:** 이 문서는 빌드·툴 판본(자동 계측·환경 식별)과 그래픽스 판본
> (측정 절차 규격·렌더 예산·시각 품질 확인)을 **PR #8에서 단일 정본으로
> 결합**한 것이다. 두 판본은 모순되지 않았다 — 빌드·툴판은 '무엇이 실제로
> 측정됐는가', 그래픽스판은 '어떻게 재고 무엇을 봐야 하는가'를 담고 있어
> 서로를 채운다. 양쪽 고유 내용은 전부 아래에 보존돼 있다.
>
> **원시 자동 측정 결과의 정본 경로는 `docs/measurements/m0-measurement.json`
> 하나다.** 같은 raw data를 다른 파일로 복제하지 않는다.
> 실행: `node scripts/measure-m0.mjs`.

## 0. 지금 확정된 것과 확정되지 않은 것

| 항목 | 상태 |
|---|---|
| SwiftShader 계측치 | **참고치 — 실제 GPU 증적이 아니다** |
| 실제 물리 GPU 실측 | ⛔ **미완료** (내장그래픽 노트북 2대 미측정) |
| 미측정값 표기 | **`null` 또는 `미실측`** — 0으로 적지 않는다 |
| 기본 품질(low/medium/high) | ⛔ **미확정** (`defaultQualityDecision=null`) |
| 드로우 콜 65 | **정적 기준선**(코드에서 센 값) — 실제 GPU 실측 완료값이 아니다 |
| INT-RENDER-013 (수심 확장) | ⛔ **최종 승인 전** |
| M0 | ⛔ **공식 종료되지 않음** |

M0 인수는 '내장그래픽 노트북 2대 × low/medium/high × 3개 시나리오' 실측을
요구한다. 이 문서는 그 표의 **틀·절차·컨테이너 참조값**을 제공하고, 하드웨어
열은 실제 노트북을 가진 창이 채운다.

# 파트 A. 측정 절차 규격 (그래픽스 판본)

## A-1. 재현 규격

- 빌드: `npm run build` 후 `dist/` 정적 서빙 (dev 모드 아님 — HMR 오버헤드 배제)
- 해상도 1280×720 창모드, 브라우저 하드웨어 가속 켜짐 확인
  (`chrome://gpu`에서 SwiftShader 아닌 실제 GPU 확인 — SwiftShader로 잡히면
  그 수치는 §A-8 실기기 표에 기재하지 않는다. 자동 판별은 §B-2 참조)
- 품질: URL `?quality=low` / (기본=medium) / `?quality=high`
- 각 시나리오 60초 주행, FPS는 성능 오버레이의 **평균 FPS**(부팅 직후 3초
  제외), 드로우 콜·삼각형은 오버레이 `draw`·`tri` 값
- GPU 메모리: `chrome://gpu` 또는 작업 관리자(GPU 프로세스)로 기록,
  텍스처 상주 추정치는 §A-3 참조

## A-2. 측정 시나리오 3종

| # | 시나리오 | 내용 |
|---|---|---|
| 1 | **협곡 일반 주행** | 출항 → 순항 심도(y=0)에서 수로 왕복 60초 |
| 2 | **폭뢰 피격 전투** | 화물선 격침 → 발각 유지(전속) → 폭뢰 피격·침수 구간 60초 (기포·wake·플래시 활성) |
| 3 | **심해 하강** | 수면(y≈11) → 최심부(y≈-19) 왕복 (심도 그레이딩 전 구간) |

> 파트 B의 자동 측정 스크립트가 현재 도는 시나리오는 기지 대기·항행·조준
> 3종으로 **이 표와 다르다** — 폭뢰 피격·심해 하강은 자동화 미구현이다(§C-1).

## A-3. 정적 렌더 예산 (코드 기준 — 실측 아님, 산출 근거 명시)

- 텍스처 상주 추정 (비압축 RGBA + mip ×1.33):
  - medium/high: 암벽 1024² + 퇴적물 1024² (각 ~5.6MB) + 금속 512² +
    마크 아틀라스 512×256 (~1.4MB + ~0.7MB) ≈ **13.3MB**
  - low(512 상한): ≈ **4.9MB**
- 파티클 상한: 프로펠러 기포 60(low)/120(med)/170(high) · 부유물
  40/140/190 · 어뢰 기포 96 (전부 1드로우 풀)
- 실시간 광원: 방향광 1 + 탐조등 SpotLight 1(그림자 없음) — 전 품질 동일
- 소나 스코프: DOM 2D 캔버스(WebGL 드로우 0), 리드로우 15Hz 상한

## A-4. 품질 단계별 시각 차이 (확인 대상)

| 단계 | 부유물 | 림라이트 | 항법등 글로우 | 텍스처 | 탐조등 빔 콘 | 기포 풀 | 프로펠러 블러 |
|---|---|---|---|---|---|---|---|
| low | 40 | off | off | 512 | off (실광원은 유지) | 60 | off |
| medium | 140 | on | on | 표준 | on | 120 | on |
| high | 190 | on | on | 표준 | on | 170 | on |

**품질과 무관하게 동일**: 안개 거리·재질 기본색·HUD·게임플레이 표시·실제
광원 수(§12.2 예산).

## A-5. 시각 품질 확인 절차 (각 조합에서 확인)

- 텍스처 404/fallback 발생 여부 (콘솔 경고 `[sceneTextures]`)
- 안개·조명·텍스처·암벽 셸 이상 유무
- 새 잠수함 모델(이중 도장·덕트 프로펠러)
- 세력 마크(태그·선박 데칼)
- 탐조등(빔·조명)
- 프로펠러 wake
- 보스 시각(3단계 구분·약점 활성/비활성·예고·최종 가속) — `?bossSpike=1`
- 소나 스코프 unwired 표시(공급자 미배선 상태에서 '계기 미연결').
  `?sonardemo=1`은 표시 규칙 fixture이며 **production wired 판정 근거가 아니다**

## A-6. 드로우 콜 기준선의 의미

**드로우 콜 65 = 코드에서 센 정적 기준선**(순항 구도, medium). 실제 GPU에서
측정한 값이 아니며, 실기기 표(§A-8)가 채워지면 그 값이 정본이 된다. 기준선은
"기능 추가로 드로우가 늘었는가"를 보는 상대 비교용이다.

## A-7. 보스 전장 밀도 기준

- 기준선: 순항 드로우 **65** (위 §A-6)
- 원칙(11차 결의 1): 보스 전장 데코는 `EnvironmentDressing` 예산의
  **재배분**이며 추가가 아니다 — 산호 18개소·어군 2종·잔해 1·원경 1겹 예산 내 이동
- **현재 진행 불가**: M1 보스 전장 레이아웃이 아직 없다. 레이아웃 도착 시
  재배분 후 기준선 대비 드로우 콜 증분을 여기에 기록한다. 기본 품질이 low로
  확정되면 상한을 low 기준으로 재계산한다.

# 파트 B. 자동 측정과 환경 식별 (빌드·툴 판본)

## B-1. 하드웨어 실측 — 미실시 (환경 제약)

**빌드·툴 창은 내장그래픽 노트북 2대를 측정할 수 없다.**
실행 환경이 헤드리스 리눅스 컨테이너이며 물리 GPU·노트북이 없다.
이 항목은 **미실시로 남기고 위장하지 않는다.**

| 요구 | 상태 |
|---|---|
| 노트북 A (내장그래픽) 실측 | ⛔ **미실시** — 하드웨어 없음 |
| 노트북 B (내장그래픽) 실측 | ⛔ **미실시** — 하드웨어 없음 |
| 그래픽스 창 수치와 교차 확인 | ⛔ **불가** — 대조할 실기기 수치가 저장소에 없음 |

교차 확인은 실기기를 가진 창이 §A-8 표를 채운 뒤에만 가능하다.
(그래픽스 창 역시 컨테이너 환경이라 실기기 FPS를 만들지 못했다 — 양쪽 창의
결론이 같다.)

## B-2. 측정 환경 (자동 기록 — 모르는 값은 null, 0으로 적지 않는다)

| 항목 | 값 |
|---|---|
| OS | `linux 6.18.5-fc-v18 (x64)` |
| CPU | `Intel(R) Xeon(R) Processor @ 2.80GHz` × 4 |
| 브라우저 | `Chromium 141.0.7390.37` |
| GPU renderer | `ANGLE (Google, Vulkan 1.3.0 (SwiftShader Device (Subzero) (0x0000C0DE)), SwiftShader driver)` |
| GPU vendor | `Google Inc. (Google)` |
| GL | `WebGL 2.0 (OpenGL ES 3.0 Chromium)` |
| **소프트웨어 래스터라이저** | **감지됨** — 일치 패턴 `swiftshader` |
| **실제 GPU 증적** | **아니오** (`realGpuEvidence=false`) |

`WEBGL_debug_renderer_info` 사용 가능: True.
**SwiftShader는 실제 GPU 증적으로 인정하지 않는다** — 도구가 이를 자동
판별해 `M0_REAL_GPU_EVIDENCE_COMPLETE=false`를 출력하며, 사람이 바꿔 적을
여지를 두지 않았다.

### 실제 GPU 증적 판정 규칙

`GPU renderer` 문자열이 소프트웨어 래스터라이저 패턴(`swiftshader`·`llvmpipe`·
`software`·`microsoft basic render`)에 걸리면 `realGpuEvidence=false`이며,
그 실행의 수치는 **§A-8 실기기 표에 기재할 수 없다.** 판정은 스크립트가
하고 문서에서 뒤집지 않는다.

### Windows·Linux 측정 환경 주의

- `scripts/measure-m0.mjs`의 `dist/` 경로 해석은 Windows에서 깨졌던 이력이
  있다(PR #11에서 수정). Windows 측정 시 이 수정본 이후 커밋을 쓴다.
- 헤드리스 리눅스 컨테이너는 `requestAnimationFrame`이 스로틀링되어 FPS가
  계단값(66.7/83.3ms)에 몰린다 — §B-4 참조.
- 실기기 측정은 **헤드리스가 아닌 실제 창 모드**에서, 하드웨어 가속이 켜진
  브라우저로 수행한다.

## B-4. 이 FPS는 tier 비교에 쓸 수 없다

프레임 간격이 66.7/83.3ms 같은 계단값에만 모여 있다 — 렌더 부하가 아니라
컨테이너 `requestAnimationFrame` 스로틀링이 만든 값이다. low와 high의
평균 차이가 1fps 안팎인데, 품질 단계는 파티클·림라이트·항법등·텍스처
상한·탐조등 빔·기포 풀을 전부 바꾸므로(§A-4) 정상 GPU라면 나올 수 없다.

| 읽을 수 있다 | 읽을 수 없다 |
|---|---|
| 세 tier 전부 부팅·로딩·루프 진입 성공 | tier 간 상대 성능 |
| 로딩 시간 | 절대 FPS·60fps 달성 여부 |
| **콘솔·페이지 오류 0건** (9/9) | 기본 품질 결정 근거 |

# 파트 C. 남은 것

## C-1. 17차 결의 대비 미실시 계측 항목

| 항목 | 상태 |
|---|---|
| 드로우 콜 수(정적 기준선 65) 실기기 대조 | ⛔ 미실시 — 계측 훅 미배선 |
| 텍스처 404 fallback 미발동 확인 | ⛔ 미실시 (자동 측정 경로) |
| 폭뢰 피격·심해 하강 시나리오 | ⛔ 미실시 — 자동 시나리오는 기지 대기·항행·조준 3종 |
| medium 60fps 판정 | ⛔ **불가** — §B-4 rAF 스로틀링으로 계측치가 판정 입력이 될 수 없음 |
| GPU 메모리 | ⛔ 미실측 (`null`) |

17차는 '사람 판단 없이 계측치가 medium/low를 결정한다'고 정했다. 컨테이너
계측치는 그 입력 자격이 없으므로 **품질 기본값 결정을 내리지 않았다.**

## C-2. 후속

1. **노트북 2대 실측** — 하드웨어 보유 창이 §A-8 표를 채운다. 절차는 §A-1,
   시나리오는 §A-2. `scripts/measure-m0.mjs`를 실기기에서 돌리는 경우
   시나리오 3종(§A-2)을 자동화 대상에 추가해야 §A-8과 형식이 맞는다.
2. **시각 품질 확인** — §A-5 항목을 각 조합에서 눈으로 확인하고 §A-8의
   '시각 이상' 열에 기재.
3. **기본 품질 결정** — §A-8 판정 기준으로 계측치가 자동 결정한다.
4. **M0 통과 판정** — 위가 채워진 뒤 통합 관리자가 내린다. **이 문서만으로
   M0 성능 통과를 선언하지 않는다.**
