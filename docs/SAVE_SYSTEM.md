# SAVE_SYSTEM — 저장 구조와 복구 정책 (빌드·툴 소유)

> 근거: 6차 대회의 결의 7 (귀환 저장·손실 규칙) · 개발 소회의(11) 결의 3
> (버전 필드 + 이중 슬롯, 체크섬·암호화 기각) · 결의 7 (스키마-마이그레이션
> 동반 커밋 규칙). 코드: `src/meta/save/`.

## 저장 매체와 슬롯

| 항목 | 값 |
|---|---|
| 매체 | 브라우저 localStorage (접근 불가 시 세션 한정 메모리 대체 — 부팅 불차단) |
| current 슬롯 | `deepDive.save.current` — 최신 저장 |
| backup 슬롯 | `deepDive.save.backup` — **직전 정상 저장** (쓰기 도중 탭 종료·캐시 손상 대비) |
| 스키마 버전 | `schemaVersion` 명시 (현재 **v1**) |
| 치트 대응 | 없음 [확정] — 싱글 오프라인에서 세이브 조작은 유저 자유 (소회의 결의 3) |

## 저장 범위 (v1)

일반 크레딧 / 희귀 부품 / 영구 업그레이드 단계(`upgradeLevels`, id는
`params/upgrades.json` 기준) / 장착 장비(`equippedGear`) / 진행
(`progress` — 단서 수·보스 개방·격파) / 저장 필요 설정
(`settings.keyboardLockNoticeShown` — 입력 안내 1회 플래그).

## 저장 시점 [확정 — 6차 결의 7]

1. **기지 귀환 정산 확정 시** — 메타 루프(리드)가 `defaultSaveStore.save()` 호출
2. **희귀 부품 획득 즉시** — 획득 판정 측이 즉시 저장 (귀환길 사망 분노 방지)

그 외 주기적 자동 저장은 **하지 않는다** — '귀환이냐 한 탕 더냐'의 긴장이
기획 의도다. 배선 요청: `docs/INTEGRATION_NOTES.md` INT-TOOL-007.

## 쓰기 절차

1. 저장할 데이터를 먼저 검증한다 (손상 데이터는 저장 경로에 들어가지 못함)
2. 기존 current가 **검증을 통과하는 경우에만** backup으로 승격
   (손상본이 정상 백업을 덮지 않음)
3. 새 데이터를 current에 기록. 실패 시 throw 없이 `false` 반환

## 로드·복구 절차 (모든 실패에서 게임 부팅을 막지 않는다)

```
current 파싱 → 마이그레이션 → 검증 ──성공──▶ 사용
      │ 실패
      ▼
backup 동일 절차 ──성공──▶ 사용 + current를 백업 내용으로 재기록(복구)
      │ 실패
      ▼
안전한 초기 상태 (createDefaultSave) — 새 게임으로 시작
```

## 마이그레이션 규칙 [리뷰 반려 기준]

- 스키마를 바꾸는 커밋은 `src/meta/save/migrations.ts`의 `SAVE_MIGRATIONS`에
  **출발 버전 → +1 버전** 함수를 반드시 동반한다. 미동반 커밋은 리뷰 반려.
- 함수 부재·미래 버전·버전 불일치는 전부 명확한 오류 → 위 복구 경로로 이관.
