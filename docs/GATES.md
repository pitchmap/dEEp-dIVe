# GATES — 게이트 G1~G9

> 마스터 플랜 §14 요약. 버티컬 슬라이스의 통과/실패는 이 게이트로만 판정한다.
> 공통 조건: 테스터 5인 중 **최소 2인은 이어폰 없이 노트북 스피커**로 테스트.

## 정의·등급·측정·미달 조치

| 게이트 | 분류 | 내용 | 등급 | 측정 방법 | 통과 기준 | 미달 시 조치 |
|---|---|---|---|---|---|---|
| G1 | 기술 | 내장그래픽 노트북 60fps (저사양 모드 허용) | **필수** | 계측 오버레이, 지정 노트북 2대 전 구간 플레이, 구간별 fps 로그 | 최저 fps ≥ 60 (또는 저사양 모드에서 60) | **롤백/일정 연장** + 희생 순서 ①~④ |
| G2 | 기술 | 초기 로딩 3초 이내, 15MB 이하 | 핵심 | 네트워크 초기화 후 접속, 계측 자동 기록 3회 평균 + `npm run check:size` | ≤15MB, ≤3초 | 2주 스프린트 (사운드 스트리밍 분리 확대) |
| G3 | 조작 | 테스터 5인 전원, 설명 없이 60초 내 첫 어뢰 발사 | **필수** | 무설명 세션, 스톱워치 관찰 (개인별 발사 시각·막힌 지점) | 5/5 ≤ 60초 | **롤백/일정 연장** + 자동 조준 보험 투입 검토 |
| G4 | 조작 | 이동·심도 조절 이해 | 핵심 | 세션 후 조작 재현 요청 | 4/5 | 2주 스프린트 (튜토리얼 힌트) |
| G5 | 조작 | 방향 상실 ≤1인, 멀미 0인 | 참고 | 세션 관찰(리센터 사용 횟수) + 사후 문진 | 상실 ≤1, 멀미 0 | 기록 후 정식 개발 이월 |
| G6 | 게임성 | 발각 이유를 자기 언어로 설명 | 핵심 | 인터뷰 "왜 발각됐나요?" 원문 기록 | 4/5 인과 설명 | 2주 스프린트 (파문·아이콘 가독성) |
| G7 | 게임성 | 폭뢰 1회+ 회피 (그중 1회는 화면 밖 폭뢰를 소리로) | 핵심 | 세션 로그 + 관찰 | 4/5 (소리 회피 1회+ 포함) | 2주 스프린트 (신관·폭뢰 수 튜닝) |
| G8 | 게임성 | 실패 원인 이해 | 핵심 | 인터뷰 "왜 졌나요?" 원문 기록 | 4/5 원인 특정 | 2주 스프린트 (피해 피드백 강화) |
| G9 | 게임성 | 재플레이 의향 | 참고 | 사후 설문 | 3/5 | 기록 후 이월 |

## 등급별 처리 [확정]

- **필수 (G1, G3) 미달:** 롤백 또는 일정 연장 — 게이트 리뷰 4문 진입 불가
- **핵심 (G2, G4, G6, G7, G8) 미달:** 2주 개선 스프린트 + 재테스트.
  방향(로우폴리 풀 3D·코어 루프)은 유지
- **참고 (G5, G9):** 수치 기록 후 정식 개발 목표로 이월

## 게이트 리뷰 4문 순차 통과제 (D+21)

1. 성능이 통과했는가 — G1·G2 계측 데이터만
2. 조작을 이해했는가 — G3~G5 관찰 기록만
3. 은신과 폭뢰 회피가 재미있는가 — G6~G9 인터뷰 원문만
4. 정식 제작으로 확대할 가치가 있는가 — 종합 의견 + 무기명 투표

**앞 문이 닫히면 뒷 문을 열지 않는다.** 1~3문에서 데이터 없는 의견 금지.

## 이 저장소의 게이트 지원 도구

- `src/ui/PerformanceOverlay.ts` — FPS·로딩 상시 표시 (G1·G2)
- `src/tools/GateMetricRecorder.ts` — 계측 JSON 다운로드 (게이트 리뷰 제출용)
- `scripts/check-build-size.mjs` — 15MB 상한 자동 검사 (G2, CI 연동)
- 커밋 `[Gx]` 태그 — 수치 변경 역추적 (`docs/BRANCHING.md`)
